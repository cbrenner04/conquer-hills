# Course file format (schema version 1)

Each course the app offers is one JSON file in `App/Resources/Courses/`, named `<id>.course.json`. Files are produced offline (by the course data pipeline or by hand), reviewed, and bundled with the app. `CourseKit` decodes and validates them; a file that fails validation is left out of the course library and logged, and a unit test fails the build if any bundled file is invalid.

Real courses are generated by the offline pipeline in `Tools/CourseTool` from inputs in `CourseData/<id>/` (see AGENTS.md, "Course data pipeline"); never edit a generated file by hand. The synthetic test course is hand-authored.

The canonical example is [`App/Resources/Courses/test-hills.course.json`](../App/Resources/Courses/test-hills.course.json).

## Conventions

- **Distances and elevations are meters.** Positions are measured from the start of the course. Miles and mph exist only in the UI.
- **Inclines are percent.** The file stores the *course incline*: the smoothed grade of the real road, rounded to 0.5%, and **signed** (downhill is negative). Treadmill limits, the baseline offset, and rounding to the treadmill's step are applied on the phone, so they can change without regenerating data.
- **Decoding is strict.** A field not listed below is rejected, so typos surface. Fields marked optional may be omitted or `null`; all others are required.

## Fields

| Field | Type | Notes |
| --- | --- | --- |
| `schemaVersion` | integer | Must be `1`. Checked before anything else. |
| `id` | string | Lowercase slug (`[a-z0-9-]+`) including the edition, e.g. `tokyo-marathon-2027`. Must match the file name. A changed route gets a new id rather than an edit. |
| `name` | string | Display name. Non-empty. |
| `edition` | string | Display string identifying the route version, usually the year. |
| `location` | string | Display string, e.g. `Tokyo, Japan`. |
| `distanceMeters` | number | Total course distance. Positive. |
| `developmentOnly` | boolean | `true` hides the course in Release builds (test data). |
| `description` | string, optional | Short description. |
| `source.route` | object | `name` (string), `url` (string, optional), `license` (string). |
| `source.elevation` | object | `name`, `url` (optional), `license`, and `kind`: `"measured"` (surveyed or recorded) or `"modeled"` (from a terrain model). |
| `source.attribution` | string, optional | Text the app must display when a license requires attribution. |
| `source.verified` | boolean | Whether a person has checked the route against official material. |
| `source.notes` | string, optional | How the data was obtained and reviewed; known inaccuracies. |
| `processing.tool` | string | What produced the file, with version. |
| `processing.generatedOn` | string | Date, `YYYY-MM-DD`. |
| `processing.parameters` | object of strings | Free-form record of the settings used. Any keys. |
| `stats` | object | `elevationGainMeters`, `elevationLossMeters` (both ≥ 0), `minimumElevationMeters` ≤ `maximumElevationMeters`. Computed from full-resolution data, not from the downsampled profile. |
| `elevationProfile.sampleSpacingMeters` | number | Positive. 100 is the standard. |
| `elevationProfile.elevationsMeters` | array of numbers | One sample every `sampleSpacingMeters` from 0, plus a final sample at `distanceMeters` (the last gap may be shorter). A 42,195 m course at 100 m spacing has 423 samples. Used for charts only. |
| `inclineChanges` | array | The course incline as change points: `{ "atMeters", "inclinePercent" }`. Each incline holds until the next change or the finish. |
| `segments` | array | Curated segments: `{ "id", "name", "startMeters", "endMeters" }`. May be empty. Standard segments (full course, halves, first and final 5K) are generated by the app and must not be listed. |

## Validation rules

1. `schemaVersion` is `1`.
2. `id` is a non-empty lowercase slug matching the file name; `name` is non-empty.
3. `distanceMeters` is finite and positive.
4. `inclineChanges` is non-empty; the first is at 0; positions strictly increase and are all before `distanceMeters`; inclines are finite, within ±30%, and multiples of 0.5; consecutive inclines differ (merge equal neighbours).
5. `elevationProfile` spacing is positive, the sample count matches distance and spacing, and every value is finite.
6. `stats` values are finite; gain and loss are not negative; minimum does not exceed maximum.
7. Each segment has a unique non-empty `id`, a non-empty `name`, and `0 ≤ startMeters < endMeters ≤ distanceMeters`.

Every problem in a file is reported, not just the first.
